# LangGraph 对话可靠性优化实施记录

实施日期：2026-10-25。基于同日诊断报告，用户授权直接实施，并允许使用 Docker 测试数据库。

## 已实现的行为

1. **协议与工具契约**
   - graph_v2 规划优先使用模型 API 的原生工具调用；仅遇到明确的能力不支持响应才在 auto 模式切换文本 JSON。
   - 可显式指定 native、json_schema、text_json。严格结构化模式使用可移植的工具名/参数 JSON 字符串封装，再按真实工具 schema 校验参数。
   - 格式错误与服务不可用分开处理；未知工具、非法参数进入有上限的纠错流程，不再静默当作“未找到资料”。
   - 工具注册表统一描述、参数约束和执行前校验；规划提示词去掉不存在的 mode 能力。新增 read_record 和 list_todos；共11个只读工具。

2. **正文与材料验收**
   - 文件有序读取返回完整的已确认段落，提供 offset、next_offset、complete 和 content_scope。
   - 日记读取和待办查询只访问现有授权视图；没有新增业务表权限或数据库迁移。
   - 正文请求不再拿文件名/描述顶替正文；多个候选具体澄清，未确认正文明确说明不能分析。
   - 图在必要时自动连续读取正文页；只读取中间页、向量摘录或单页，不能据此宣布全文覆盖。
   - 同一正文片段先取得短摘录、后取得完整段落时，完整段落会替换摘录并保留引用身份。
   - 本轮正文上下文上限为64000字符，自动正文读取上限为12页。超过上限或后续读取失败时返回 partial_answer，并在正文说明只能分析已读取部分。

3. **错误与回答终态**
   - 可选工具失败时保留已有材料继续分析，并说明实际限制；完全没有可用材料时报告读取失败。
   - 初始向量查询失败后仍可通过关键词等只读工具恢复。
   - 成功查询得到零条待办、零计数等是可回答结果。
   - 空回答、输出长度截断、服务拦截、缺少正常结束原因、伪工具调用都不能标记为成功回答。
   - XML 标签属性、代码围栏、规划 calls JSON、嵌套 function JSON 等常见伪调用受控；用户明确请求协议示例时保留示例。
   - 只允许在没有发布正文时进行一次输出修复；正文已发出后发生错误，不会拼接另一整段答案。
   - 模型传输中断会保留已发布的部分回答，并报告 output_error 和真实 has_partial_answer。

4. **诊断与运行副本**
   - 完成/失败事件保留实际降级原因和提示词输入哈希。
   - graph_v2 服务端结构化日志包含 run_id、终态、材料状态、正文页数/字符数、规划协议、模型结束原因、输出修复次数、运行目录和构建版本。没有记录模型密钥或正文原文。
   - 构建系统可以设置 MIRROR_AI_BUILD_VERSION；未设置时明确记录 unknown。
   - 已用现有同步脚本同步 upload，并单独验证从 upload 目录导入模块和编译图。

## 配置

`config.example.yml` 的 `agent.planning_protocol` 默认 auto，可选 native、json_schema、text_json。默认先尝试原生工具；鉴权、限流、服务端错误和无效工具 schema 不触发协议降级。旧后端 chat/chat_stream/json_task 的接口和行为保留。

## 使用边界

本次修改已在本地验证，没有推送、部署或重启现有业务服务。真实模型的理解和分析质量仍需用实际选用的模型做回归；这里验证了协议、材料传递、控制流和授权边界，不把合成模型响应当作真实模型质量评测。

超长正文会明确标注部分覆盖。结构化输出与原生工具的实际支持以配置的模型端点为准；可显式选择兼容的 text_json，而不会把协议不支持、参数错误或服务失败解释成资料不存在。
